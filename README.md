# 하리나 매치룸

스타크래프트 CK, PL, 랜능크, 빨무 대진을 한 화면에서 관리하는 웹앱입니다.
차콜 블랙을 바탕으로 라벤더·딸기우유 핑크와 하트·별 포인트를 더한 큐트 다크 테마입니다.

## 주요 기능

- 팀과 선수(이름, 티어, 본종) 등록
- 갓·킹·잭·조커·스페이드·0~8티어·유스 드롭다운 선택
- CK·PL 경기별 부종 선택
- 부종리그 및 선수별 부종 사전 등록
- 세트를 추가한 뒤 세트별로 일반·위너스·나락전 방식 선택
- 위너스는 승자 잔류·패자 탈락, 나락전은 패자 잔류·승자 통과
- 위너스·나락전 종료 조건: 전원 탈락/통과 또는 지정 경기 수
- 운영자가 필요할 때 에이스 결정전 직접 추가·삭제
- 랜능크·빨무 기본 랜덤 및 저티어 지정 종족 선택
- 세트 추가 및 세트별 1·3·5·7·9·11경기 설정
- 5·7·9경기 등 세트 경기 수에는 마지막 에이스 결정전이 포함되며 자동으로 `ACE` 표시
- 맵과 세트별 대진 순서 입력
- 경기 승패, 세트 다승팀 및 전체 세트 스코어 자동 계산
- PC 한 화면 활용을 위한 기본 밀집형 레이아웃 및 전체화면 버튼
- 가로 폭을 줄이고 팀과 주요 영역을 위에서 아래로 배치한 세로형 구성
- 선수·맵·종족·승리팀을 한눈에 보여주는 경기 진행 현황 요약판
- 경기 진행 현황의 세트별 실시간 경기 스코어와 세트 승자 표시
- 상단 설정, 가운데 좌우 팀/현황 패널, 하단 전체 폭 대진표 구성
- PC 가로화면에서 여백·글자·입력칸을 확대한 와이드 레이아웃
- 승패 입력 후 다음 순번 대진을 자동으로 `진행 중` 표시
- 대진 운영과 별풍 정산을 분리한 탭 화면
- 별도 룰렛 탭에서 맵 목록 편집 및 무작위 추첨
- 입력한 항목 수에 맞춰 룰렛 원판을 균등 분할하고 각 칸에 이름 표시
- 당첨된 맵을 현재 진행할 경기의 맵 칸에 자동 입력
- 등록 선수 중 팀장 2명을 지정하고, 룰렛 당첨 팀장에게 다음 팀원 선택권 부여
- 최근 룰렛 결과 기록
- 메인펀딩·입장료·메인펀딩+입장료 비율 정산
- 팀 등록 인원과 1인당 입장료를 기준으로 팀별·1인당 지급액 계산
- 정산 결과에서 승리팀·패배팀 선수 이름별로 받아야 할 별풍선 개수 표시
- 각자 방송에서 선입 받은 입장료는 대진표의 최초 상대와 선수당 1회만 차액 정산
- `지급자 → 수령자`와 실제 지급·수령 개수를 선수별로 표시
- 양 팀 등록 선수별 개별 펀딩 입력 및 전체 자동 합산
- 공용 메인펀딩과 선수별 펀딩을 합쳐 팀 비율로 분배
- 브라우저 자동 저장
- JSON 백업 및 복원
- 새 버전 배포 시 실행 중인 화면에서 자동 감지 및 새로고침
- 스폰노트를 iframe 없이 통합페이지 내부 모듈로 실행하고 기존 `spawnNote.records.v1` 기록을 그대로 연동
- 스케줄 달력에서 스폰노트 기록을 날짜별로 집계해 저그전·테란전·토스전의 경기 수와 승패를 자동 표시
- 맞혀도랑을 iframe 없이 통합페이지 내부 모듈로 실행하고 기존 `starPredictionManager_v31` 예측·참가자·대진을 그대로 연동
- 맞혀도랑의 중복 로고·PC/모바일 전환·자체 업데이트 버튼 제거
- 맞혀도랑 경기 추가와 대진표 관리에서 공용 선수 DB 기반 티어·종족 자동 입력
- 덕몽 & 폴가이즈 최종 순위와 팀 점수를 1080px PNG 이미지로 저장·공유
- 버전 표시 충돌로 발생하던 무한 화면 갱신을 제거하고 초기 렌더·이미지·탭 모듈 로딩을 경량화
- 상단의 큰 HARINA 전용 로고와 `하리나 매치룸` 제목 옆 도랑이 캐릭터 적용
- 방송 송출 탭에서 16:9 송출 화면 미리보기 제공
- 대회명·세트 스코어·현 세트 스코어·맵·현재 대진·진행 상태·다음 대진 표시
- 송출 화면을 별도 창으로 열고 운영 화면 변경을 실시간 반영
- 다크 배경과 투명 배경 모드 선택

## 업데이트 방식

`main` 브랜치의 파일이 변경되면 GitHub Pages에 자동으로 배포됩니다. 페이지를 열어둔 사용자는 1분 간격으로 새 버전을 확인하며, 새 버전이 확인되면 자동으로 새로고침됩니다. 사용자 입력 데이터는 브라우저에 별도로 저장되어 업데이트 후에도 유지됩니다.

GitHub Pages 주소: https://hanuri2000-svg.github.io/star-match-manager/

## 공용 선수 마스터 DB

- `players.json`을 티어·종족 공용 원본으로 사용합니다.
- 통합 티어표, 맞혀도랑, 스폰노트가 같은 선수 DB를 읽도록 구성합니다.
- 공용 선수 DB는 화면에 노출하지 않고 선수명 입력 시 티어·종족 자동 입력에 사용합니다.
- GitHub Pages 정적 구조이므로 사이트 화면에서 `players.json`을 서버에 직접 덮어쓰지는 않습니다. 원본 변경은 저장소 업데이트로 반영합니다.

## 토너먼트 연결 복구

게임컴과 송출컴은 `tournament-transport.js`의 공용 연결 관리를 사용합니다. 중계 서버 연결이 끊기면 같은 Peer ID로 재연결하고, 15초 동안 응답하지 않는 연결은 정리합니다. 송출컴은 5초 간격으로 현재 대진 전체를 요청하며, 연결 복구 시 즉시 결과·팀 배치·대회 설정을 다시 받습니다. 끊긴 동안에는 마지막 방송화면을 유지합니다.

재시도 타이머는 하나만 사용하며 1초부터 최대 30초까지 간격을 늘려 연속 8회까지 시도합니다. 이후 인터넷 연결 복귀, 브라우저 화면 복귀 또는 페이지 복귀 이벤트에서 다시 시도합니다. 같은 방을 다른 게임컴이 사용 중이면 방을 빼앗거나 반복 재시도하지 않습니다.

회귀검사: `node --test tests/tournament-transport.test.mjs`
전체 검사: `node --test tests/*.test.mjs`

실기 확인: 두 컴퓨터에서 같은 방송 링크로 연결한 후 인터넷을 끊었다 복구하고, 끊긴 동안 변경한 경기 결과가 송출컴에 반영되는지 확인합니다. 브라우저를 잠시 숨기거나 기기를 절전 상태로 전환한 뒤 복귀해 같은 동기화와 기존 순위 팝업 닫기를 확인합니다. 자동 검사는 가상 PeerJS 이벤트와 타이머를 사용하며 실제 중계 서버/기기 테스트를 대체하지 않습니다.
